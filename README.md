# The London Choral Service — website

Source for [londonchoralservice.com](https://londonchoralservice.com) — professional funeral singers, wedding choirs, and ceremony musicians across the UK. The trading site of Alma Consort Ltd.

Hand-authored static HTML (~165 pages), no framework. Hosted on GitHub Pages with a custom domain.

## Quick start

```sh
git clone https://github.com/lucawetherall/londonchoralservice
cd londonchoralservice
# edit sources (css/*.css, partials/*.html, or page HTML)
./build.sh                    # concat CSS, expand partials, inline CSS, generate sitemap + dates, validate
python3 -m http.server 8000   # preview at http://localhost:8000
```

## How deployment works

There is **no CI build step**. That's why `./build.sh` must be run before committing any change to `css/` or `partials/`: the built output is the deployed artifact. A rebuild rewrites the inlined CSS and expanded partials in every page, so a ~165-file diff after a style change is expected. `sitemap.xml`, `data/page-dates.json` and `llms-full.txt` are generated by the same script.

The site serves an allowlist, not the whole repo. On each push to `main`, [`.github/workflows/deploy-pages.yml`](.github/workflows/deploy-pages.yml) copies the public files (the `PUBLIC` list in [`scripts/stage_site.py`](scripts/stage_site.py): pages, `assets/`, `css/`, `fonts/`, `js/`, and root files such as `robots.txt` and `sitemap.xml`) into the Pages artifact, unchanged, and deploys that. Everything else here (docs, logs, scripts, data, tests, partials, `.claude/`) returns 404 on the site. Pull requests run the same checks without deploying, and `./build.sh` runs them locally. After a deploy, `python3 scripts/check_live_site.py` confirms what the live site serves.

This needs Settings → Pages → Source set to **GitHub Actions**; "Deploy from a branch" would serve every file again. The repo itself is public on GitHub, so nothing secret belongs in it.
