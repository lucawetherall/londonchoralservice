# Christmas Expansion & Seasonal SEO Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Load `writing-site-copy` before writing any visible text, `new-page` before creating any new page, and `build-and-verify` before any partial, bulk, or build work.

**Goal:** Turn a single corporate-only Christmas page into a seasonal cluster that wins two distinct head-term families — *carol service* and *hire carol singers* — before the September booking peak. Twelve net-new pages (1 service, 4 B2B, 7 guides), a repaired and rebroadened `christmas.html`, a Christmas pricing policy stated on `pricing.html`, localised Christmas sections on all 52 area pages, and Christmas promoted into the nav and footer.

**Architecture:** Hand-authored static HTML, cloned from exemplars — never written from scratch. New pages clone `christmas.html` (for `carol-singers.html`), `for-event-managers.html` (for the four B2B pages), and `music-guides/best-christmas-carol-singers.html` (for the seven guides). No new CSS components: everything reuses existing classes, so `css/` is untouched and the ~106-file inlining diff is produced by exactly one `./build.sh` in Task 7. Shared files — `sitemap.xml`, `llms.txt`, `music-guides/index.html`, `partials/*` — are edited serially by a single owner, never by two parallel content workers.

**Tech Stack:** Static HTML + inlined CSS (regenerated by `build.sh`), Python `validate_jsonld.py` for schema validation, `python3 -m http.server 8000` for preview. No test framework — verification is grep-based invariants, JSON-LD validation, build success, and browser preview at 375/768/1280px.
